1. OWASP Security Defense Headers

Browser-level security enforcement policies

When a browser requests your web pages, HTTP Response Headers instruct the client browser on how to restrict malicious scripts, frames, and resource loading. जब कोई ब्राउज़र आपकी वेबसाइट लोड करता है, तो वेब सर्वर HTTP Response Headers के जरिए ब्राउज़र को निर्देश देता है कि दुर्भावनापूर्ण स्क्रिप्ट्स (XSS) या फ़्रेम्स (Clickjacking) को ब्लॉक करना है या नहीं।

Strict-Transport-Security (HSTS) SSL Stripping Defense

What it is: Instructs browsers to strictly communicate over HTTPS, preventing unencrypted HTTP fallbacks.
Threat Vector: Without HSTS, active network eavesdroppers can execute SSL Stripping attacks to intercept cleartext passwords.
Remediation (Nginx): क्या होता है: ब्राउज़र को बाध्य करता है कि वह हमेशा सुरक्षित HTTPS कनेक्शन पर ही जुड़े।
खतरा (Hacker Vector): अगर यह गायब है, तो पब्लिक Wi-Fi या नेटवर्क पर हमलावर कनेक्शन को असुरक्षित HTTP में डाउनग्रेड (SSL Stripping) करके पासवर्ड्स चुरा सकता है।
फ़िक्स (Nginx):

add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;
X-Frame-Options Clickjacking Defense

What it is: Prevents your web pages from being embedded within external third-party iframes.
Threat Vector: Attackers overlay an invisible iframe of your application to trick authenticated users into executing unwanted actions (Clickjacking).
Remediation (Nginx): क्या होता है: आपकी वेबसाइट को किसी अज्ञात फ़िशिंग साइट के <iframe> में लोड होने से रोकता है।
खतरा (Hacker Vector): हैकर एक अदृश्य फ़्रेम बनाकर यूज़र से अनजाने में 'Delete Account' या 'Transfer Funds' जैसे संवेदनशील बटन क्लिक करवा लेता है (Clickjacking)।
फ़िक्स (Nginx):

add_header X-Frame-Options "DENY" always;
Content-Security-Policy (CSP) XSS & Data Theft Defense

What it is: Restricts which domains can execute JavaScript scripts, styles, or load external images.
Threat Vector: Unrestricted execution allows Cross-Site Scripting (XSS) payloads to hijack user sessions and keylog credentials.
Remediation (Nginx): क्या होता है: ब्राउज़र को व्हाइटलिस्ट नियम देता है कि JavaScript और Styles सिर्फ़ आपकी वेबसाइट या चुनिंदा डोमेन से ही लोड होंगी।
खतरा (Hacker Vector): क्रॉस-साइट स्क्रिप्टिंग (XSS) अटैक होने पर हैकर की इंजेक्टेड स्क्रिप्ट्स यूज़र के टोकन्स और कुकीज़ चुरा लेती हैं।
फ़िक्स (Nginx):

add_header Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline';" always;
X-Content-Type-Options MIME Sniffing Prevention

What it is: Forces browsers to strictly respect the declared Content-Type header without sniffing.
Threat Vector: Prevents malicious uploads disguised as non-executable files from being executed as scripts.
Remediation (Nginx): क्या होता है: ब्राउज़र को फ़ाइलों के MIME-type का मनमाना अनुमान (MIME sniffing) लगाने से रोकता है।
खतरा (Hacker Vector): हैकर किसी .jpg इमेज फ़ाइल के अंदर JavaScript छिपाकर अपलोड कर देता है, जिसे ब्राउज़र स्क्रिप्ट समझकर चला देता है।
फ़िक्स (Nginx):

add_header X-Content-Type-Options "nosniff" always;

2. Exposed Network Ports & Database Services

Perimeter firewall hardening & entry points

Every network daemon listens on a port. Only HTTP (80) and HTTPS (443) should be exposed publicly. Database and internal service ports must be isolated. सर्वर पर हर सेवा एक पोर्ट नंबर पर सुनती है। इंटरनेट पर केवल वेब पोर्ट्स (80 / 443) ही खुले होने चाहिए। डेटाबेस और आंतरिक प्रबंधन पोर्ट्स कभी भी सार्वजनिक नहीं होने चाहिए।

Port 3306 (MySQL) & 5432 (PostgreSQL)

Threat: Distributed botnets launch brute-force credential attacks against exposed database ports.
Fix (UFW): sudo ufw deny 3306/tcp खतरा: ऑटोमेटेड बॉट्स लगातार ब्रूट-फ़ोर्स पासवर्ड्स ट्राई करते हैं या रिमोट एसक्यूएल कनेक्शन खोलते हैं।
फ़िक्स (UFW): sudo ufw deny 3306/tcp

Port 6379 (Redis) & 27017 (MongoDB)

Threat: Unauthenticated key-value stores can be dumped, modified, or held for ransom within minutes.
Fix: Bind daemon configuration strictly to bind-address = 127.0.0.1. खतरा: डिफ़ॉल्ट रूप से पासवर्ड न होने पर हैकर्स पूरा डेटा डिलीट या डंप करके रैनसमवेयर (Ransomware) मांगते हैं।
फ़िक्स: Bind address को 127.0.0.1 पर सेट करें।

3. Sensitive Dotfile Leaks (.env, .git, backups)

Source code & credential disclosure prevention

Accidental deployment of repository files or environment configs allows anyone to download secret API keys and proprietary source code directly via HTTP GET requests. डेवलपमेंट के दौरान .env, .git, या backup.zip फ़ाइलें गलती से पब्लिक वेब डायरेक्टरी में रह जाती हैं, जिन्हें कोई भी ब्राउज़र से डायरेक्ट डाउनलोड कर सकता है।

Universal Nginx Dotfile Deny Rule: Insert this rule to block all hidden configuration files: यूनिवर्सल Nginx डॉटफाइल ब्लॉक रूल: अपने Nginx सर्वर ब्लॉक में ये नियम जोड़ें:

location ~ /\.(?!well-known) { deny all; return 404; }

4. Session Cookies & CORS Security Flags

Prevent session hijacking & cross-origin data theft
• HttpOnly: Prevents client-side scripts from reading session cookies via JavaScript (document.cookie). JavaScript (document.cookie) को कुकी पढ़ने से रोकता है ताकि XSS अटैक में सेशन टोकन चोरी न हो सके।
• Secure Flag: Ensures cookies are only transmitted across encrypted TLS/HTTPS channels. कुकी को केवल एन्क्रिप्टेड HTTPS कनेक्शन पर ही ट्रांसमिट होने की अनुमति देता है।
• SameSite (Lax / Strict): Protects against Cross-Site Request Forgery (CSRF) exploits on sensitive endpoints. क्रॉस-साइट रिक्वेस्ट फ़ॉर्जी (CSRF) हमलों से यूज़र सेशंस को सुरक्षित रखता है।
• CORS Misconfiguration: Never combine wildcard origin * with credentials Allow-Credentials: true. कभी भी Access-Control-Allow-Origin: * के साथ Allow-Credentials: true न लगाएं।
